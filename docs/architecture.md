# Архитектура

## Общая схема

Харнес асинхронно отправляет логи каждого шага в брокер. Микросервис на Go выступает в роли Consumer Group, вычитывая данные в своем темпе (паттерн **CQRS/EDA**).

```text
┌──────────────┐   produce (key: run_id)   ┌───────────────────┐
│ Test Harness │ ─────────────────────────▶ │ Apache Kafka      │
│  (producer)  │                           │ topic:            │
└──────────────┘                           │ agent-harness-    │
                                           │ metrics           │
                                           └─────────┬─────────┘
                                                     │ consume (GroupID:
                                                     │ agent-metrics-analyzer)
                                                     ▼
                                           ┌───────────────────┐
                                           │ Go-микросервис    │
                                           │ (Consumer + API)  │
                                           └────┬─────────┬────┘
                              ┌─────────────────┘         └─────────────────┐
                              ▼                                             ▼
                    ┌──────────────────┐                          ┌──────────────────┐
                    │ PostgreSQL 16+   │                          │ Neo4j 5+         │
                    │ метаданные,      │                          │ граф траекторий   │
                    │ агрегаты         │                          │ (Run/Step)       │
                    └──────────────────┘                          └────────┬─────────┘
                                                                          │ GET /v1/runs/{run_id}/trajectory
                                                                          ▼
                                                                 ┌──────────────────┐
                                                                 │ React-дашборд    │
                                                                 │ (React Flow)     │
                                                                 └──────────────────┘
```

## Принципы

*   **Асинхронность:** харнес не ждет обработки — публикует событие и продолжает работу.
*   **Независимый темп:** микросервис вычитывает сообщения в своем темпе, отделен от продюсера скоростью и схемой.
*   **Двойная запись:** данные параллельно сохраняются в реляционное (агрегаты) и графовое (траектории) хранилища.
*   **Доставка At-Least-Once:** оффсет коммитится синхронно только после успешной записи в обе БД.
