# AGENTS.md

## Цель
Правила работы агентов в репозитории с чистой архитектурой.

## Архитектура
Соблюдать слоистость:
- `domain/` — ядро. Только бизнес-сущности, value-objects, доменные ошибки, порты (интерфейсы). Без фреймворков, без инфраструктурных импортов.
- `application/` — use-cases. Зависит только от `domain`. Не знает о presentation/infrastructure.
- `infrastructure/` — адаптеры. Реализует порты из `domain`. Может использовать фреймворки/БД/HTTP.
- `presentation/` — транспортный слой. Зависит от `application`. Маппит внешние модели во внутренние.

**Зависимости строго внутрь:** `presentation -> application -> domain`. Обратных зависимостей быть не должно.

## Правила работы
- Перед изменением — прочитать файл и понять контекст (импорты, соседние файлы)
- Не создавать новые файлы, если есть подходящее место в существующей структуре
- Следовать существующему стилю кода (нейминг, форматирование)
- Не добавлять комментарии без явного запроса
- Не коммитить изменения без явного запроса пользователя
- Не менять конфиги (tsconfig, eslint, prettier) без обоснования и запроса

## Code style
- Предпочитать явные типы там, где это уместно
- Использовать интерфейсы для портов в `domain`
- Исключить циклические импорты
- Не использовать `any` без веской причины
- Соблюдать инкапсуляцию доменных сущностей

## Тестирование
- Проверять решение тестами при наличии скриптов: `npm run test`, `npm run lint`, `npm run typecheck`
- Если скриптов нет — спросить, какие команды запускать
- Писать/править тесты по месту существующей практики

## Безопасность
- Никогда не логировать и не коммитить секреты/ключи
- Не трогать `.env*`, если нет прямого указания

## Коммиты
- Коммитить только по явному запросу. Осмотреть `git status/diff` перед коммитом. Сообщение краткое и по делу.
